# Warframe Nyana Manual

本仓库维护 Warframe 的配卡文案、配卡图、黑话解释，以及供内容系统加工使用的辅助资料。主要可直接引用的内容是配卡文案和黑话正文；其他资料需要经过对应系统解析、组合或核实后使用。

## 目录架构

仓库根目录对应原项目的 `warframe-content/source/`。下表使用当前实际目录名：用户所说的 `build` 对应 `builds/`，`build-image` 对应 `build-images/`。

```text
.
├── builds/                    # 战甲、宠物/同伴、武器等配卡文案
├── build-images/              # 配卡图片与文案引用的图片素材
├── slang/                     # 黑话解释、俗称及实体别名
│   ├── replies/               # 可直接引用的文字解释
│   ├── visual/                # 支持图标、图片和变量的黑话文档
│   ├── market/                # 市场查询使用的物品别称映射
│   └── *.md                   # 战甲、武器、Mod 等实体别名表
├── guides/                    # 玩法、刷取指南，交由对应功能处理
├── market/                    # 市场查询相关目录与配置
├── resources/                 # 资源与获取相关资料
├── variables/                 # 可复用内容变量与片段
├── weekly/                    # 周常、轮换及相关说明资料
├── riven-market/              # 紫卡市场相关配置与资料
└── command-prefix-filters.md  # 命令前缀过滤规则
```

| 内容层 | 作用 | 引用方式 |
| --- | --- | --- |
| `builds/` | 战甲、宠物/同伴、武器等配卡文案；现有内容也包含载具 | 根据关键词或别称找到方案，引用配卡正文及其关联图片 |
| `build-images/` | 存放配卡图和正文图片素材 | 根据文案中的相对路径引用 |
| `slang/` | 解释大量游戏黑话，并维护俗称和别名 | 解释类条目可直接回答“船员是干什么的”“钢木是什么意思”“工程化是什么”“主9是什么意思”等问题；别名表用于定位实体 |
| 其他目录与文件 | 指南、资源、变量、周常、市场资料和配置 | 不作为可直接引用的通用回答资料，先经过对应功能解析、展开、组合或核实 |

“其他”是用途分类，并非名为 `其他/` 的目录。部分资料即使包含可读正文，也应按所属业务处理。

## 配卡文案与图片的关系

`builds/` 保存文字方案，可以说明适用场景、操作手法、配置要求与注意事项；`build-images/` 保存对应的配卡图。方案可按战甲、武器、同伴等类别分目录，也可沿用已有英文实体目录。

例如，现有 `builds/战甲/nova/加速静音.md` 的 `图片：战甲/nova/加速静音.png`，指向 `build-images/战甲/nova/加速静音.png`。修改图片文件名或目录时，应同步更新文案引用。

```markdown
# 方案名称
- 战甲：Nova
- 关键词：方案名称、适用玩法
- 别称：玩家常用叫法
- 图片：战甲/nova/配卡图.png

## 操作手法
这里填写操作说明。

## 注意事项
这里填写配卡要求与适用条件。
```

此模板用于说明文案组织方式，图片路径请替换为实际存在的文件；武器和同伴条目应沿用各自现有格式。

## 黑话内容的组织

`slang/replies/` 存放可以直接引用的文字解释。例如现有 `船员.md` 说明船员的用途和相关要求，`钢木.md` 解释玩法并给出操作建议。工程化、主9等术语也按解释类内容组织。

```markdown
# 术语名称
- 关键词：术语名称、另一种常见写法
- 别称：俗称、简称
- 分类：玩法分类

这里直接解释术语的含义、用途和相关注意事项。
```

`slang/visual/` 适合需要图标、图片或变量展开的解释；引用前需完成渲染或展开。`slang/market/` 和根目录实体别名表用于名称解析，不能把别名映射元数据当成解释正文。详细格式见 [文字黑话说明](slang/replies/README.md)、[可视黑话说明](slang/visual/README.md) 和 [市场别称说明](slang/market/README.md)。

## 关键词与别称约定

黑话解释和配卡文案均可设置关键词与别称：

- 关键词描述条目的检索入口，可填写多个。
- 别称用于补充简称、俗称和其他叫法，可以省略整行。
- 关键词与别称允许重复，也允许不同条目使用相同的词；不要求全仓库唯一。
- 遇到多个条目命中同一词时，应结合分类、实体、用途和上下文选择或展示候选，保留原有内容。
- 现有黑话格式兼容 `关键词` / `关键字`、`别称` / `别名`；编写时建议统一使用 `关键词` 和 `别称`。

这些是内容编写与消费约定。本仓库保存内容源；实际命令路由、重复命中的处理及渲染行为由接入它的程序实现。现有子目录说明中的命令行为应以所用程序版本为准。

## 内容使用流程

```text
用户提问 / 查询词
        ↓
根据意图、关键词、别称与上下文定位条目
        ├── 配卡 → builds 正文 + build-images 图片
        ├── 黑话解释 → slang/replies 正文，或展开后的 slang/visual 内容
        └── 其他功能 → 解析所属资料，完成加工后输出
```

新增内容时优先沿用同类条目的格式；文案和图片分开维护。引用内容应保留其中的条件、限制和上下文，避免只摘取别称或配置片段造成误解。
