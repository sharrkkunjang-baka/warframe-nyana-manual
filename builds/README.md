# 配卡 Markdown 写法

每套配卡单独建立一份 .md，建议路径：`builds/实体类别/实体名/配卡名.md`。元数据必须且只能填写一个 `战甲`、`武器`、`同伴`、`守护`或`载具`；中英文正式名和审核别名都会解析到同一 canonical 实体。

示例：

```markdown
# 防御牛吼
- 战甲：Nidus
- 用途：防御、生存
- 图片：nidus/防御牛吼.png
- 别名：牛吼防御

## 配置说明
关键词：配置

父卡正文会保留在所有子卡上方。

#### 石头选择
关键词：石头、碎片

这里写石头要求。查询“配卡 Nidus 石头”时只高亮该子卡，并保留“配置说明”父卡上下文。

#### 操作手法
关键词: 手法关键词：手法、操作

这里写操作手法。
```

图片相对于统一受控资源根 `source/build-images/`，例如上例实际文件为 `build-images/nidus/防御牛吼.png`。正文中可单独一行写 `{p|相对路径}` 插入真实图片；支持 png/jpg/jpeg/webp，中文和空格路径可用。绝对路径、URL、UNC、`..`、符号链接和越界路径均拒绝，坏图只显示可读提示，不会拖垮整份配卡。图片每次渲染读取，替换文件后无需重启。

单独一行 `{n|页面标题}` 会从该处强制开始新图片，并把文字作为续页标题；这与超高后的自动分页不同，两者可共同工作。空标题显示“未命名页面”，不会泄漏原变量文本。

`##` 创建父卡，`####` 只在所属父卡内部创建子卡。标题后的 `关键词：词1、词2` 属于当前节点；不同子卡关键词互不串联。普通段落不会自动拆成卡片。旧文档只写 `##` 时仍按原父卡方式显示。

武器示例只需把元数据改成：

```markdown
- 武器：Boltor
```

载具示例：

```markdown
- 载具：Railjack
```

如果该 canonical 实体没有 Markdown，Bot 会明确回复“暂未收录”，不会生成配卡文案。
